# Lizicut v0.1.1 复审

2026-10-22。对照原项目本地源码、三份 XMind 的完整主题树与财经风格稿，检查规则是否保留、是否有意改写、智能体能否实际执行，并直接修复发现的问题。原项目源码基线为 `06c43b66e08f0dbf5df56eddbf66c7aae1dc5208`。未发布 GitHub。

## 结论

v0.1.0 已有正确的解释方法，但“背景、元素、模板”的独立选择和编排、主持责任链、素材取得后的落地要求不够具体；合成器也缺少独立叠层。这会使智能体倾向于制作整帧字卡，或者停在分镜/提示词阶段。

v0.1.1 已补齐这些规则与执行路径，修复选中音视频流时长校验、原声保护和示例的延迟揭示问题。现已实际完成文稿/虚构数据 → 解释单元 → 测量句段音频 → 素材/画面 → 字幕/时间线 → MP4 的完整示例，以及独立图层的竖屏示例。实现不依赖旧站运行。

“智能体可按这套方法完成”仍有条件：当前环境需要实际的素材取得、转录/配音或复杂动画工具。Skill 提供判断、交接和现成本地合成能力，不会凭规则自动获得这些外部能力。未做独立智能体盲测，不能承诺任意智能体、任意素材都能一次成功。

## 执行修复的证据

- 30 项自动检查通过，其中 8 项为实际 FFmpeg 媒体集成测试。检查了图层的独立起点、透明区域、层次、淡出和共同退出；分别构造视频长/声音短及相反情况，确认在导出前拒绝越界。无解说图文配乐已实际导出，不必伪造 narration 轨。
- 多轨过滤图会增长到 Windows 命令长度上限，因此长图改为临时文件读取；增加48条独立短音效、共50条音轨的实际导出验证了该分支。本机 FFmpeg 9 可用，未把这个短片测试当作长片吞吐或内存测试。
- 用不同频率的实际音频信号测量配乐分量：原声区间降低、200ms 短间隙保持、结束后逐步恢复。它证明已安排轨道的包络执行，不能证明语音识别或人工听感。
- [完整示例](../examples/revenue-profit/README.md)：63.00 秒，1280×720，25 fps，1575 帧，H.264/AAC；实际导出并完整解码。首句已经谈到两个指标，原先利润图形到第二句才出现，已改为同句完整对照；补简化成本口径说明。
- [分层示例](../examples/layered-edit/README.md)：9.36 秒，720×1280，25 fps，234 帧，H.264/AAC；实际导出并完整解码。循环背景不随字幕重置，元素与模板分别入场；视频叠层使用独立源入点。横屏图表直接缩小时字过小，已为竖屏重新排版。
- 两例真实 MP4 的关键状态已做作者视觉自检；来源索引、Markdown 相对链接、UTF-8、示例媒体合同均纳入本地检查。字体来自本机，不随包分发。

## 语义场景走查

这是同一作者按修订规则的走查，不是独立评审或成功率测量。

| 输入 | 应有的剪辑判断及实际核对 |
|---|---|
| “增长12%”，没有其他数据 | 口径明确的数字强调；不能捏造趋势。规则具备反例，示例数据有完整计算基础。 |
| 一个年份 / 多个演变节点 | 单个年份可作标签；只有时间关系值得看时才使用时间线。 |
| “他说”，没有原始声音 | 查到文字来源则准确引用；没有来源保留缺口，不生成波形或仿原声证据。 |
| 多句话共同解释反馈机制 | 同板推进节点与回路，不按逗号或每句重搭场景；完整示例6镜承载12句。 |
| 长段复杂解释 | 给状态推进与阅读留时间，按功能安排呼吸，不硬凑纯画面配额。 |
| 主播素材有含糊词时间和自然停顿 | 保守句段切分，保护语气，低置信度不冒充高置信度；实际字幕助手拒绝跨切口猜词。 |
| 真人不出镜，但需要可信解释 | 稳定人物/公司/证据锚点接责，不强造虚构主持或随机吉祥物。 |
| 资料音频需要观众听清 | 显式保留 original 轨并降低音乐，不能只保留视频而自动丢声；媒体测试已覆盖。 |
| 横屏改竖屏 | 重排文字、图表和字幕安全区；新增实际竖屏示例。 |
| 只有文案，且没有可用声音工具 | 可做估算分镜和素材；明确缺少声音环节。静音固定时长需符合用户目标，不能拿它替代要求的有声成片。 |
