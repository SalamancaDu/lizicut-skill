# Premiere 主执行流程

在文稿、录音、粗剪、素材和动效决策落入真实 PR 工程时使用。剪辑取舍继续遵循 [剪辑规则](editorial-rules.md)、[口播与时间](timing-and-roughcut.md)、[视觉与声音](visual-and-sound.md)；这里说明怎样操作及核查，不能用工具默认模板代替编辑判断。

## 发现工具与保护现有工程

推荐执行端：[DutchErwin/PremiereMCP](https://github.com/DutchErwin/PremiereMCP)。它通过本机 CEP 桥接操作 Premiere，Skill 本身不安装或启动该项目的服务。其他 MCP 只要具备所需能力也可使用；不要要求客户端必须叫 Codex 或 Claude。

1. 发现当前可用的 Premiere MCP。采用精简工具目录的服务器先 `search_tools`，必要时 `get_tool_schema`，再以真实名称和参数 `invoke_tool`；不要因为顶层只出现几个工具就认定不能剪辑，也不猜工具名或参数。
2. 实际编辑前调用 `verify_premiere_connection`。仅探查且不需要启动应用时可设 `launchIfNeeded:false`。失败后按返回的具体原因处理；`retry:false` 且要求用户动作时，报告 `nextStep` 并停止依赖连接的操作，不用盲重试测试桥接。安装、客户端配置、权限调整不由本 Skill 自动执行。
3. 读取项目路径、实际序列、项目项、轨道和设置。不要凭窗口中的同名项目或旧 ID 继续操作。修改已有任务时复制序列，保留原序列；新建视频使用独立工程。切换工程前保留未保存工作，不能覆盖或关闭用户未保存内容。只对本次目标工程和序列写入。
4. 记录真实画幅、帧率、音频采样率、颜色与交付范围。用实际已安装的 `.sqpreset` 建序列，或从正确素材/已有序列派生。设置变更后读回，不把请求的 25fps 当作实际成功。

工具名是本次可发现的示例，不是所有 MCP 的共同接口。桥接、序列或操作结果不确定时先读实际状态，确认已做了什么，再决定补做；不能靠整段重复调用恢复。

## 文稿和录音确认

入口中的两次确认都需要具体对象，记录在已有制作说明或对话即可，不额外建立审批系统：

- **文稿**：准确文件/文本版本、可改范围、主体、数字/单位/时期、解释结构及未解决事实。给用户看的稿件与随后用于字幕、画面和录音的稿件一致。事实待核实不等于可以生成一个看似可信的证据画面。
- **录音**：实际源文件、所用轨道、时长/帧率、主收音、转录依据及补录问题。需要时先同步双机或独立收音，并保留偏移；不得对不同源直接复用同一入点。转录工具缺失时可利用可靠字幕和实际声音，不能用字数匀分冒充词时间。
- 已确认版本不重问。换录音或实质改稿时只重新核对受影响部分，更新后续字幕、粗剪和画面。用户明确委托智能体定稿/选录音时保留该授权及实际选择依据；未取得用户确认就如实标记。技术测试可锁定自制夹具，不能写成用户已审阅或真人表演已验收。

## 从口播决定到 PR 粗剪

先在源时钟下决定保留区间及理由，再实施。源时钟、片段局部时间和序列时间是不同坐标；剪掉一段后所有依赖使用同一映射。

| 保留源区间（秒） | 放入序列（秒） | 含义 |
|---|---|---|
| `[0, 3.6)` | `[0, 3.6)` | 保留第一遍完整表述 |
| `[7.2, 12.96)` | `[3.6, 9.36)` | 删除中间重复，后段前移3.6秒 |

以上仅演示映射，不是所有录音的切点。序列落点按真实帧率换算；必要取整记录误差，源音视频保持同一范围。不能把源时间7.2秒误当成第二段的序列起点。

可用 `import_media` 获取源项目项，再用 `add_to_timeline` / `add_to_timeline_batch` 的 `sourceInPoint`、`sourceOutPoint`、`time` 和实际轨道放入保留片段。同期视频默认保留关联原声；外录音使用已核对的同步偏移单独上轨。工具对秒、帧或 ticks 的约定按 schema 和实际回读确认，不把字符串 tick 值直接当秒。

也可以在序列副本上切分、修剪与波纹删除。多段原地删除通常从后向前，防止前段删除移动后续坐标；完成后重新枚举片段，旧 clip ID 和轨道索引可能失效。不能混用重建方案与旧序列位置重复删减。

每批后读取轨道，核对各片段的源入/出点、序列起止、同期音频、间隙及总长。批量接口可能部分成功，按逐片结果和实际序列恢复，不能把顶层响应当全部成功。添加切口、删减理由及待复核标记；置信度不足的内容先保留。逐个检查接缝，按 [原规则](timing-and-roughcut.md)处理呼吸、动作和跳切。

本包 roughcut / retime-captions 可以辅助计算字幕与映射；PR 中仍使用原始媒体的真实源区间，不先把整段压成 MP4 再冒充可编辑粗剪。字幕使用粗剪后的序列时钟。

## 素材取得、设计与导入

先按 [素材搜索](material-search.md)解决每个镜头/图层的实际用途。检索和生成使用本次可用工具；Premiere MCP 不是素材库、ASR 或生图服务。资料事实与生成示意分开记录；生成后仍需检查身份、文字、结构、比例、时长和循环。

选定文件落盘后再导入 PR，按用途放入素材箱。读取导入结果，以实际路径找到项目项并关联到镜头/图层；仅下载或导入素材箱不代表已经剪入序列。需要透明图层时核查 alpha 和边缘，不能把普通黑底 MP4 当透明素材。

在实际画幅下确定定版、字幕安全区与动作意图，再实施。优先在 PR 完成简单裁切、位置、缩放、透明度、效果和关键帧；准确图表/节点等需要独立运动时保留独立素材。PS/Illustrator 定版及 AE 复杂动效按 [Adobe 协作](adobe-collaboration.md)处理；不强制每个镜头都经过三种软件。

## PR 编排、动效和声音

- 轨道按用途组织即可，例如底画面、解释图层、重点、字幕，以及口播、资料原声、音乐、音效；不要假定每个工程有相同轨道数量或固定 V/A 编号。
- 覆盖素材用明确源区间和序列起止。覆盖视频若自带音频，先决定是否需要；`linkAudio:false` 等选项须确认不会把现有旁白覆写，完成后读回相关音频轨。
- 先发现实际效果和组件名称，再设置属性或关键帧。中英文显示名、Position 单位、Scale 基准和关键帧时间坐标可能随宿主/接口变化。先在目标片段检验一个已知状态，回读键及对应实际帧，再推广；不要硬套未经验证的像素/归一化坐标或整片统一缓动。
- 图层入场、稳定阅读和交接按真实语句安排。只有句级时间就保守揭示关系；需要词级落点先取得时间证据。读取 `get_keyframes` / `get_value_at_time` 等并抽帧核对，写入成功不单独证明动效可见。
- 标题可以使用真实存在且可修改所需字段的 MOGRT；先确认模板路径和字段，不凭工具名称假定可以从空白生成任意中文标题。没有模板时可用已制作并保留源文件的透明图层。
- 调整口播、资料原声、BGM 与音效。需要 ducking 时按真实声音区间安排包络，核查 gain/音量单位与回读结果。短接缝淡化不替代被切掉的音素；不得让新上轨素材自动覆盖已剪口播。

## 字幕与最终对齐

按实际保留声音校对最终 SRT，导入并通过 `create_caption_track` 等生成真实字幕轨。对起点、跨切口、句尾、数字单位、中文断行和字幕安全区逐项核对。PR 的 DOM 可能读不到完整字幕文本，不能把空读回当成空字幕或检查通过；结合源 SRT、轨道/导出结果与实际帧确认。

在序列时钟下核对首、中、尾同步以及每个新切口。分别检查背景换镜、前景入场、板面更新、字幕换行和声音事件，不把它们强制绑成一个切点。用片段句柄确定目标后再改动；修剪和插入之后重新检查受影响落点及末帧。

PR 原生字幕轨与最终视频字幕可见性是两件事。导出需明确烧录、外挂或嵌入方式，检查实际预设和输出；仅有 SRT 项目项或字幕轨不能证明 MP4 内可见。需要把图文作为烧录交接素材时仍保留可编辑字幕和生成依据，并如实记录实现方式。

## 保存、导出和交付

1. 保存实际 `.prproj`。检查所用媒体、字体、第三方效果、图层、字幕和实际输出区间；处理离线素材、无意间隙、静音/隐藏轨道及会拉长片尾的残留片段。
2. 发现真实可读 `.epr`。`get_encoder_presets` 可能只列用户预设；空列表不证明本机没有编码器，可核对实际安装目录中的预设或用户提供的文件。不能捏造预设路径或随包分发 Adobe 预设。
3. 核对预设控制的容器、画幅、帧率、颜色、音频和字幕；`format` / `resolution` 等提示字段不保证覆盖预设。先做 `validate_project_for_export` 等检查，再将目标序列和输出路径交给导出工具。
4. AME 接受队列只表示已提交。若有可靠完成状态就读取；没有监控能力时检查输出文件稳定、进程/作业状态及完整解码，不机械重复提交。失败或仅提交就报告该状态，不改用 FFmpeg 拼出一个文件声称 PR 导出成功。确需改执行端先说明差异并取得相应选择。
5. 用实际视频核查规格、总长、首中尾和每个关键切口/动效/字幕，检查声音。结构回读、可解码、自检和独立人工审片分别说明；没有实际观看/核听的范围不得写成通过。

交付实际 PR 工程、关联素材和字幕；根据需要保留 PS/AI/AE 源及中间渲染。收集或重链接媒体时以本次范围为限，不移动用户原素材。交付后至少验证可重新打开或重链接的工程；只有 MP4、XML、决策 JSON 或工具响应不等于可编辑 PR 成片。

## 工具缺口时

保留已完成工程与明确缺口，继续不依赖失败步骤的工作。桥接缺失、某效果不支持、字幕不可读、AME 未完成和生成服务不可用分别说明；不把其中一个问题泛化成所有工具都不可用。FFmpeg 是辅助检查、素材预处理或用户选择的备用执行端，不能悄悄取代本次 PR 交付。

接口与宿主限制以实际 schema/回读和执行结果为准。参考：[MCP 项目](https://github.com/DutchErwin/PremiereMCP)、[已知限制](https://github.com/DutchErwin/PremiereMCP/blob/main/KNOWN_ISSUES.md)。
