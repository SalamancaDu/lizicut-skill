# Lizicut · 让画面承担解释工作

把用户的表达意图转成可观看、可理解、可继续编辑的视频。沿用已有内容、素材、品牌和工具，默认采用克制的财经解释风格；用户指定的题材与风格优先。单纯转码、下载或裁切不需要整套流程。

## 接续本次任务

从对话和实际文件恢复准确文稿、可改写范围、受众、已有录音/字幕/视频、规格和交付终点：方案、资产、预览或成片。已有结果从缺口继续，不重新采访或重做所有阶段。未指定比例时可从 16:9 开始；这只是默认值。

缺失信息只有在改变表达、正确性或真实外部动作时才询问。缺音频可先做语义草案和估算时长；不得把估算冒充强制对齐。图文配乐或明确静音的视频可按阅读与节拍设计固定时长，不必强加 TTS；不能拿这条路径替代用户要求的有声解说。用户要求先审阅时停在该节点，否则连续完成已授权阶段。

## 剪辑判断

1. **先抓解释任务。** 通读整篇，明确问题、论点、证据和收束。按观众要看懂的关系组织解释单元；标点辅助字幕定位，不自动决定换镜。
2. **决定画面如何工作。** 区分载体（主播、实拍/资料画面、设计画面）、信息关系（比较、变化、流程、空间等）与证据来源。分别选择背景、前景元素和信息模板，按解释需要组合；不是每镜都集齐三层。主播与实拍都可以叠加结构化信息。一个单元先有一个主解释任务，再加入必要辅助表达。
3. **锁定时间依据并处理口播。** 有录音时以实际声音为主时钟。先区分转写错误、真实重录、语义重复与自我纠正，再决定删减；重录择优不默认留最后一遍。保留有效换气、句头句尾、限定和转折；按真实切口处理呼吸与跳切。粗剪后同步更新音视频、字幕和源时间映射，置信度不足的候选先保留。
4. **取得所需素材。** 先用现有且合适的素材，按镜头/图层的具体用途检索。打开原页与实际内容，先核对身份、证据和使用条件，再比较解释效率、构图与可用时长。搜索词和生成提示词分别写；生成图像承担示意、氛围或隐喻，不能代替事实证据。选定后下载/采集到本地，保留出处、选择理由、授权状态与镜头绑定；链接或候选预览不算完成。
5. **组织阅读与连续性。** 模板文字提炼关键词和关系，字幕保留准确口播。相邻语句仍解释同一关系时沿用板面、物件或坐标并推进状态。需要新对象、新证据或新阅读任务时再换板。
6. **让动作与声音服务理解。** 先把图层挂到真实语句/关键词上，再安排入场、可读保持和交接；只有句级时间时保守呈现完整关系，不捏造词级落点。默认前快后稳，硬切与有目的的推拉为主；BGM 按段落发展，旁白和原声都应听清，音效只强调有意义的事件。
7. **交付到实际终点。** 需要成片时继续合成、导出和回看。发现内容、时序或阅读问题，回到拥有问题的源层修复，并更新受影响产物。

具体选择读 [剪辑判断与画面选择](references/editorial-rules.md)；处理录音、粗剪和字幕读 [音画时间](references/timing-and-roughcut.md)。不要为执行分类额外调用旧站模型，当前智能体可直接根据这些规则判断。

## 按需使用资料

- 新建财经/商业解释视频，或需要统一整片气质：读 [财经解释风格](references/finance-profile.md)。其他题材沿用用户风格，不强行套财经外观。
- 素材、证据板、背景、版式、动效、配乐或音效需要制作：读 [视觉与声音](references/visual-and-sound.md)。
- 需要实际检索、挑选、下载或导入素材：读 [素材搜索与落盘](references/material-search.md)，沿用已有工具；无素材管理后端时可用 materials 助手。
- 要合成、导出或把工作交给另一个工具：读 [执行与时间线](references/execution.md)。使用用户已有后端；本包提供 Python 标准库 + 已安装 FFmpeg 的本地合成路径。
- 需要理解来源或调整默认规则：读 [提取来源与取舍](references/source-notes.md)。历史材料中的“必须”是当时项目约束，只有本次仍适用的部分才沿用。

## 本地工具

下列路径相对于本 Skill。使用当前环境的 Python；先确认已有 FFmpeg/ffprobe，缺失时说明具体能力缺口，不自动引入新服务。

```text
python scripts/lizicut.py doctor
python scripts/lizicut.py roughcut roughcut-plan.json --output-dir output/roughcut --render
python scripts/lizicut.py materials material-plan.json --output-dir output/materials --download
python scripts/lizicut.py validate timeline.json --media
python scripts/lizicut.py retime-captions original.srt cuts.json --output captions.srt
python scripts/lizicut.py render timeline.json --output film.mp4
python scripts/lizicut.py inspect film.mp4 --decode
```

合成器接受主画面、独立叠加的透明图片/视频、SRT 和声音轨，执行裁切、适配、图层时序与透明淡入淡出、字幕、混音及导出。复杂图表、形变、遮罩、运镜和转场先在所选工具中制作，再交给合成器；分镜里的自然语言不会自动变成动画。检索和语义筛选由智能体调用当前可用工具；materials 助手可复制本地文件或下载已核验候选的普通 HTTP(S) 直链，校验文件并记录来源，不自动完成 ASR、语音克隆或付费生成。

口播任务先读 [音画时间与粗剪](references/timing-and-roughcut.md)，以现有剪辑后端保留可编辑工程。没有指定后端时，roughcut 入口可将已核对的删减计划转成同步时间线、字幕、源时间映射和切口复核点，并导出视频 MP4 或音频 WAV；它不自行作出语义删减决定。

## 最少交接与完成判断

简单任务用短说明即可。多镜头制作维护一份现有时间线或简洁分镜：口播范围、时间依据、解释目的、背景/元素/模板、素材与来源、关键词、各层进出/阅读时间、声音、选择理由及真实文件。从候选到落盘的缺口在这份记录中解决；仅有搜索词、链接或提示词的镜头尚不可渲染。使用本包合成器时才按其 JSON 合同写文件；不要同时维护几套重复状态。

检查实际目标尺寸下的阅读、图表口径、素材身份、字幕/音频同步、切点、画面边界和声音，再检查实际导出文件。文件可解码和时间线合法证明技术连通，不单独证明剪辑审美或解释有效。自检与独立人工审片分别说明。

交付用户要求的视频，并保留可继续修改的实际工程/时间线、关联素材和字幕；说明字体及缺失依赖，不只留下压平的 MP4。搜索词、提示词、计划、静帧、预览、正式视频分别报告完成状态。工具不足时交付可用部分并指出缺失环节，不把资产清单说成成片。发布、付费、上传和权限变化只在用户已授权范围内执行。
